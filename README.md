# ⚡ CSL-Meter

**Is your AI subscription actually serving the model you paid for?** CSL-Meter
probes subscription & API plans and scores consistency, substitution risk and
latency from real measurements.

AI coding plans and API resellers all *claim* a model name — `kimi-k3.1-pro`,
`claude-opus-*`, and so on — but what reaches your editor is whatever the
gateway decides to serve. CSL-Meter is a public observatory that checks: it
sends a fixed battery of real probe requests through a plan, fingerprints the
responses, and publishes a **CSL index** (Consistency, Substitution & Latency)
per plan — with the raw distributions attached, so anyone can re-derive every
number.

## Live demo

**https://konspace.cc**

The demo deployment is access-gated while it runs on measured data, and every
reading on it carries an explicit origin label:

- **Simulated** — simulated baseline data, seeded for display. Never mixed
  into verified aggregates.
- **Server-Verified** — generated by a real probe battery against the
  provider's official endpoint, executed and stored by the server.

If a number has no label, it isn't a measurement. That rule is enforced in
code, not in policy: simulated rows cannot flip a plan to "verified", and the
site-wide status only turns `verified-live` once *every* listed plan carries
at least one Server-Verified sample.

## Quickstart

Pure Python 3 standard library — no dependencies to install.

```bash
# 1. Clone
git clone <this-repo> csl-meter && cd csl-meter

# 2. Configure (placeholders are documented inline)
cp .env.example .env   # then fill in real values; at minimum set a gate hash

# 3. Run
./run.sh               # binds 127.0.0.1:8090; put a reverse proxy in front
```

`./deploy.sh` initializes the database and runs the full test + security
audit suite before first serving.

## How it works (method summary)

- **Number-distribution fingerprinting.** The probe battery asks the model to
  pick numbers under a fixed protocol. Each model family has a characteristic
  response distribution; Jensen–Shannon divergence (JSD) against golden
  baselines yields the nearest-profile ranking and the substitution signal.
- **Cross-harness de-biasing.** The same battery runs under four harness
  framings (raw, Claude Code, Cursor, OpenCode). A reading only counts as
  consistent when the identification agrees across framings.
- **Reasoning-aware extraction.** Reasoning models may burn the whole token
  budget thinking and return an empty message body. The extractor reads the
  number from the visible content first, then inline `<think>` blocks, then
  the `reasoning_content` channel — before concluding anything.
- **Insufficient content is a non-result.** If fewer than 8 distribution
  samples yield an extractable number, the battery is rejected
  (`INSUFFICIENT_PROBE_CONTENT`) and **no report is filed** — an exhausted
  reasoning model must never be misreported as "identified as another model".
- **Hard token budget.** Every battery is capped at **30,000 tokens** of real
  upstream usage; crossing the cap aborts the run with no report.
- **Zero credential retention.** Submitted API keys are used in memory only;
  a truncated SHA-256 dedup hash is all that is ever stored.

The full methodology — including the five acceptance thresholds and the
honest-labeling rules — lives in [docs/methodology.md](docs/methodology.md).

## Calibration: help us make the baselines trustworthy

The golden baselines behind the fingerprint comparison are **still being
crowd-calibrated**. A nearest-profile result is only as honest as the baseline
it is compared against, and today some baselines lack verified captures from
genuine first-party endpoints. Until a baseline is calibrated, readings are
published as *"distribution does not match the claimed model's baseline"* —
never as proof of substitution.

**This is the project's main open call for contributions:** if you hold a
first-party API key for a baseline model, you can submit a calibration capture
(raw probe responses from the official endpoint, re-derivable by anyone) —
see [CONTRIBUTING.md](CONTRIBUTING.md).

## Repository layout

| Path | What it is |
|---|---|
| `app.py` | Web server, JSON API, badges, access gate, Turnstile enforcement |
| `csl_engine.py` | Probe engine, fingerprint/JSD scoring, SQLite store, migrations |
| `scripts/run_live_t3_t4_eval.py` | Live evaluation CLI (consistency & account-risk measurements against a real key) |
| `scripts/security_audit.py` | Credential-retention / SSRF / fail-closed audit suite |
| `tests/` | Unit & integration tests (real local HTTP upstreams, no mocks of the wire) |
| `docs/methodology.md` | Formal methodology and reporting rules |
| `run.sh` / `deploy.sh` | Local run / first-deploy verification |
